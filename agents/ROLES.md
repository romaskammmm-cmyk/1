# 🎭 Роли

## Координатор (`coord-1`, один на команду)

Делает ПЕРВЫМ после регистрации:

1. Разбивает ЦЕЛЬ ПРОЕКТА на задачи по 15–40 минут каждая, независимые по файлам.
2. Создаёт `tasks/queue/t01.json`, `t02.json`, ... строго по `tasks/_TEMPLATE.json`:
   - `id`, `title`
   - `description` — чёткое ТЗ: что сделать + критерии приёмки
   - `outputs` — точные пути файлов, которые должен создать воркер
   - `priority` — число, 1 = самое важное
   - `depends_on` — массив id задач, которые должны быть в `done/` до старта
3. Пишет broadcast о старте: сколько задач, общий план.

Далее работает циклами:

- sync → читать inbox + broadcast + registry всех агентов → отвечать и помогать;
- зависшие задачи (автор молчит дольше 20 минут) — вернуть в `queue/`, сообщить в broadcast;
- проверять готовые задачи (`done/` + файлы в `project/`), при браке — вернуть в `queue/` с замечанием в поле `result`;
- финал: `project/REPORT.md` (что сделано, структура, как запускать) + `comms/broadcast/DONE.md`.

Координатор может сам брать задачи из очереди на общих основаниях, если свободен.

## Воркер (`worker-1`, `worker-2`, ...)

Бесконечный цикл:

1. `git pull --rebase`.
2. Прочитать `comms/inbox/<AGENT_ID>/` и свежие файлы `comms/broadcast/`. Есть `DONE.md` → финиш (раздел 9 протокола).
3. Если нет активной задачи — взять из `tasks/queue/` (раздел 5 протокола).
4. Работать над задачей, heartbeat каждые ~5 минут, промежуточные коммиты + push.
5. Завершить задачу → push → вернуться к шагу 1.

Запрещено: создавать задачи, трогать чужие `outputs`, останавливаться молча (всегда оставляй heartbeat или сообщение).
